一、背景与目标

本需求为新建菜单「系统管理 - 马甲包管理」（此前不存在），用于管理供推广渠道使用的 APK 马甲包。本期新建该菜单及其列表页与表单框架。

因推广渠道管理侧（安装类型包含 APK 时的「选择马甲包」）当前急需可供选择的成品 APK 包，功能按两期上线：

  • 一期（本次）：搭建菜单与表单框架，仅上线「上传」功能——本地上传成品 APK 包，上传后进入列表，供推广渠道管理「选择马甲包」调用。
  • 二期（后续）：完整打包功能（「新增」入口），不在本文档范围内。
目标：让运营能把现成的 APK 成品包录入系统，即刻成为推广渠道管理的可选马甲包。

二、一期范围与边界

本期做

  • 新建「系统管理 → 马甲包管理」菜单及列表页。
  • 新增「上传」按钮及上传弹窗，支持本地上传单个 .apk 成品包，系统解析包信息并入列表。
  • 上传记录支持「编辑」（可重新上传替换 APK）与「删除」（二次确认 + 关联校验）。
  • 补做推广渠道管理「选择马甲包」与本菜单的联动（见第六节）。

本期不做 / 界面处置

  • 完整打包功能为二期：列表操作区「新增」按钮本期置灰禁用，「操作说明」按钮隐藏。
  • 暂仅支持 APK 包类型。
来源区分：上传记录在「备注」栏默认标记 本地上传。原型统一维护在 prototype.html（系统管理 → 马甲包管理）。

三、功能设计

3.1 菜单与入口

新建菜单：系统管理 → 马甲包管理。进入为列表页，含筛选区（地区 / 商户 / 推广渠道 / 打包进度 / 包类型 / 后台显示名称 / 最后操作人 / 创建时间）与数据列表。

列表页右上操作区含「上传」按钮，点击弹出「上传马甲包」弹窗；「新增」按钮本期置灰禁用（二期打包功能），「操作说明」按钮隐藏。

3.2 上传表单字段

「上传马甲包」弹窗字段如下：

字段控件必填选项 / 说明
地区下拉必填选择所属地区，如「巴西」。
商户下拉必填选择所属商户号，如「762」。选项随地区联动。
推广渠道下拉暂停用本期暂未启用：下拉默认「全部」（仅此一项），保存后列表「推广渠道」列显示 - -；筛选区同仅「全部」。
包类型下拉必填下拉选择，当前选项仅 APK 一项。
后台显示名称输入框必填运营自定义的识别名，展示在列表「后台显示名称」及前台「选择马甲包」下拉中。全局不允许重复（保存时校验，编辑时排除自身）。
上传APK包文件选择必填本地选择单个 .apk 文件；仅支持 .apk 格式，单个不超过 100MB。上传后系统解析（见第四节）。
包名称（如 com.xxx）、APP名称不在表单中手填，由系统解析 APK 得到；包ID 由系统生成（非 APK 解析）。均无需人工录入（见第四节）。自动
表单不含「备注」字段：备注由系统自动填写为 本地上传（用于区分来源），无需运营录入。

3.3 编辑

列表中本地上传记录的「编辑」操作，弹窗字段与上传弹窗完全一致，并预填该条已有信息（地区、商户、推广渠道、包类型、后台显示名称）。

  • 允许重新上传 APK 包替换：重新选择文件后系统重新解析，回填新的包名称、APP名称（包ID 不变，仍为该记录原有系统 ID）；不重新上传则保留原包信息。
  • 保存后原地更新该行，并刷新「最后操作时间」。
  • 包类型固定 APK 不可改；包名称由解析生成、只读。

3.4 删除

点击「删除」弹出二次确认。确认弹框文案（沿用现有风格）：

标题「温馨提示」；正文「确认是否要删除该条配置信息？」；按钮「取消 / 确定」。

点击「确定」后先做关联校验：检查是否有推广渠道或官方渠道关联了该 APK 包——

  • 无关联：删除该记录。
  • 有关联：不允许删除，提示「该包已被推广渠道或官方渠道关联，不允许删除」，记录保留。

3.5 操作区图标

本地上传记录的操作列含两个图标：✎ 编辑、🗑 删除。图标鼠标移入显示文字说明（「编辑」「删除」）。

列表列结构预留二期打包功能所需的字段与操作（如打包相关图标），本期不实现；本地上传记录不涉及打包，操作仅编辑、删除。

3.6 下载地址交互

列表「下载地址」列显示为省略形式（https://...），并提供：

  • 悬浮完整地址：鼠标移入以浮层显示完整下载地址（如 https://upload-us.q-4-g-r.com/s4/6112906/KK678.com_400196.apk）。
  • 复制图标：地址后置复制图标，点击复制完整地址并提示「链接已复制」。

保存与删除时逐项校验，未通过则阻断操作并给出对应提示（Toast）；保存类提示后停留在弹窗，待修正：

触发时机校验 / 错误场景提示文案

四、系统解析 APK 与校验

用户选择 APK 文件后，系统对文件进行合法性校验与信息解析：

4.1 解析成功

校验通过后，系统从 APK 解析出包名称、APP名称，并由系统生成包ID、存储生成下载地址，一并回填至记录（表单区提示解析出的包名称 / APP名称，无需人工输入）：

字段来源用途
包名称解析 APK 包名（packageName）列表「包名称」列，如 com.braz.kk678apk。
APP名称解析 APK 应用标签（label）列表「APP名称」列。
包ID系统生成 非 APK 解析列表「包ID」列，记录唯一标识。生成规则：6 位数字，以 100 开头，从 100001 起依次自增（100001、100002、100003…）。编辑重新上传不改变已有包ID。
下载地址系统生成 文件存入对象存储后的 URL列表「下载地址」列，供下载安装与前台调用。
关于「本地上传是否有下载地址」：有。系统接收 APK 后存入服务器 / 对象存储并生成可访问 URL，写入「下载地址」列——即用户 / 推广渠道实际下载安装的地址。
母包版本为二期打包功能相关字段，本地上传记录不适用，该列显示 - -（详见第五节）。

4.2 解析失败

当文件非合法 APK（格式错误、损坏、无法读取包信息等）时，给出错误提示并阻断保存，提示文案示例：解析失败：文件损坏或非合法 APK，请重新上传。用户需重新选择文件方可继续。

五、保存后列表呈现

点击「保存」，校验通过后新记录插入列表，字段取值规则：

列表列本地上传取值
地区 / 商户 / 后台显示名称来自上传表单填写
推广渠道- -（本期暂未启用）
包名称 / APP名称系统解析 APK 得到
包ID系统生成（6 位数字，100001 起自增）
包类型APK
下载地址系统生成的存储 URL
备注本地上传（系统自动填写，非表单录入）
创建时间 / 最后操作时间 / 操作人系统按当前时间与登录账号记录
打包进度- -（二期打包功能字段，本地上传无打包过程）
母包版本- -（二期打包功能字段，本地上传不适用）
APP图标（下载）- -（二期打包功能字段；本地上传图标已内嵌于 APK，无单独图标资源）
二期打包功能相关字段对本地上传记录统一显示 - -：打包进度、母包版本、APP图标（下载）。其余字段照常。筛选区「打包进度」相应含 - - 选项，用于筛出本地上传记录。

六、与推广渠道管理的联动

推广渠道管理中「安装类型」包含 APK 时提供「选择马甲包」入口。本次需求需补做该入口与本菜单的联动。

6.1 联动逻辑

  • 「选择马甲包」下拉的数据源为本菜单的马甲包列表：读取满足匹配条件的 APK 包供选择。
  • 匹配条件：地区、商户一致（推广渠道本期暂未启用，暂不参与匹配）。
  • 下拉项展示「后台显示名称」；选中后带出该包的下载地址与包名称，供渠道安装配置使用。
  • 本菜单上传成功的 APK 包即时可选，无需额外发布操作。
删除约束：已被推广渠道或官方渠道关联的马甲包不允许删除（见 3.4）。参见《PRD · 推广渠道管理模块》。

八、异常与边界

场景处理
非 .apk 文件 / 超过 100MB选择时即拦截，提示格式或大小限制，不进入解析。
APK 损坏 / 无法解析包信息提示「解析失败：文件损坏或非合法 APK，请重新上传」，阻断保存。
必填项未填（显示名称 / 未上传文件）提示对应必填校验，阻断保存。
解析出的包名称等与已有记录重复允许重复，不校验、不拦截（包名称、APP名称等可重复）。
后台显示名称与已有记录重复不允许：拦截并提示「后台显示名称已存在，请修改」。
上传后需修改「编辑」弹窗预填信息，字段同上传弹窗，可重新上传 APK 替换后保存；「删除」二次确认后移除。
编辑时重新上传解析失败同上传：提示错误、阻断保存，保留原记录不变。
唯一性约束：仅后台显示名称全局唯一；包名称、APP名称等其余字段允许重复。
